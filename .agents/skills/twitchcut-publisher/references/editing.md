# 編集と最終検査

## 内容を理解して選ぶ

原本・Chat・ASR・画面の調査をVODごとに共用する。原本の全時間範囲を確認して話題一覧を作り、コメント密度だけで採否を決めない。元配信の時刻と完成動画の時刻の対応をEDLに保存する。字幕の低信頼区間、固有名詞、聞き違いが疑われる箇所は実音声と比較し、必要なら別の日本語対応ローカルモデルで対象範囲を再認識する。外部ASRへ送らない。旧本文、比較結果、採用根拠、未確定箇所を残す。

| 種別 | 編集方針 |
|---|---|
| Shorts | 一連の会話が短い時間で理解できる場面。前振り、展開、オチ、反応を残す。尺のために語尾を切らない |
| Topics | ひとつの話題を独立して理解できる横動画。必要な前提から始め、展開・反応・オチまで残す。無関係な盛り上がりの連打を冒頭に足さない |
| Digest | 配信全体の会話と作業・ゲーム等の進行が分かる編集版。冒頭約10秒に実際の見どころを使い、その後は文脈が分かる順序へ。必要なら1時間超も可 |

反復は文・やり取り単位で整理し、意味を変える継ぎ接ぎを避ける。話していない待ち時間は原則2秒以内へ詰めるが、笑い、返答を待つ間、意味のある作業や余韻は残す。無音/VADやASRの境界は候補であり、発話完結性の証明ではない。

## EDL、字幕、画面

リポジトリの`docs/edit-format.md`を読み、対応しているフィールドだけを使う。切点は入力の実尺で検証し、字幕・ぼかしの時刻が元時間か出力時間かを混同しない。改訂前のEDL・成果物は保存する。

字幕は聞こえた発話に基づく。既定では本人は白文字と青縁、実際のコメント読み上げは白文字と明るいピンク縁`#F76AF8`。本人がコメントを復唱した部分は本人の役割。根拠がない話者ラベルを付けない。編集注は発話字幕と見た目で区別する。

このPCにある日本語フォントを明示し、配布元固有の書体を必須にしない。字幕は原則2行以内、自然な文節で区切り、実出力で読みやすい大きさと位置を確認する。目安の文字数へ機械的に詰めるために文字を小さくしない。顔、主要な絵、ゲームHUD、字幕同士の重なりを確認する。

Shortsは元映像の縦横比を保った拡大と意図した切り抜きを使い、主役を見切れさせない。Topics/Digestもキャラ・絵を横長へ引き伸ばさない。同時刻の元映像と書出し画像を比較し、実際の頭・顔・絵の形、画面の充填を確認する。出力寸法/SARが正しいだけでは合格にしない。

外部画面、個人情報、不要な管理画面等は必要な時刻と矩形を実フレームで特定してぼかす。画面変化、切点の延長で復活した範囲、拡大・トリミング後の座標を再確認する。別配信のぼかし座標や時刻を流用しない。

## 音声

`source_preserve_v1`を使用する。元音声に話者別増幅、発話単位の持ち上げ、単一パス`loudnorm`を加えない。補正済みの過去音声を新規jobに引き継がない。元配信にある音の問題と、書出しで新たに発生した問題を区別する。

最終音声を同じcutsから作った元PCMと対応づけ、ゲインの揺れ、時間ずれ、元にない残差を確認する。AAC再圧縮由来の差はあり得るため、単純なバイト一致を要件としない。レンダーのPCM比較結果を読み、疑わしい箇所は実音声で調べる。大きな音量変化やノイズを低い合格しきい値で隠さない。

効果音、BGM、アバター、末尾案内は自動で必須にしない。利用者が用意し、使用できる素材がある場合だけ内容に合う使い方を検討する。追加音源が必要なら元音声保持の検査と混同せず、意図した混音を別に確認する。

## 最終出力の検査

最終MP4の全体decode、映像・音声ストリーム、寸法、尺、形式を確認する。書出し結果の冒頭、終端、全切替点、字幕の切替、画面変化、ぼかし範囲を調べる。すべての境界で直前直後の元音声と完成音声を比較し、語尾・笑い・返答が残っていることを確認する。

実際のフレームと音声を確認できないツール環境では、その項目を未確認とする。波形、ASR、VAD、スクリーンショットだけで「全編視聴済み」「全境界聴取済み」と言わない。機械検査で分かる結果と、本人の確認が必要な箇所を整理する。

QAは`review/<asset-id>.json`へ集約し、最終SHA、使用したEDL、実検査の根拠を結びつける。失敗した再検査の前の合格を再利用しない。ファイル変更時は新SHAに対応する検査を行う。最終の尺、本数、Topicsの平均尺、完成時間軸での章を記録する。
