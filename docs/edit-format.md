# 編集データとレンダー

`scripts/render.py` は、調査済みの編集データ（EDL）からショート・話題別横動画・ダイジェストを作ります。元配信のどこを採用するか、発話が完結しているか、字幕が正しいか、ぼかしが必要かは Codex が実素材から判断して記録します。レンダー成功は視聴・聴取の合格を意味しません。

## 実行

リポジトリ直下の PowerShell で、初期設定後に実行します。

```powershell
./.venv/Scripts/python.exe scripts/render.py --edl workspace/edits/sample.json
```

`--config twitchcut.local.json` で設定ファイル、`--output` で保存先を指定できます。パスは設定した workspace の内側に限ります。相対的な `source`・`output`・`outro.image` は **EDL のある場所ではなく workspace 基準**です。`--edl`・`--config` は通常のコマンド実行場所基準です。

既定の出力は `workspace/outputs/<id>.mp4` です。ここは制作確認用です。投稿対象は、制作ジョブの `delivery` 配下の正しい区分へ明示して出力してください。

```powershell
./.venv/Scripts/python.exe scripts/render.py --edl workspace/edits/sample.json --output Archives/twitch_1234567890/Shorts/sample.mp4
```

`1234567890` は実際のジョブ ID に置き換え、横動画は `Topics`、ダイジェストは `Digest` にします。ジョブを作らずにこの例の番号をそのまま使わないでください。

同じ出力・元動画・EDL・レンダーコード・フォント等で、検査済み SHA が一致する再実行は既存結果を再利用します。内容が変わった完成品は、通常は上書きを拒否します。改訂を確定して `--force` を付けると、旧 MP4・ASS・SRT・結果 JSON を出力先の `revisions/<id>/<UTC日時>/` へ保存してから置き換えます。元素材は変更しません。

## EDL schema 1

以下は**形式説明用**です。時刻・発話・ぼかし位置を実際の素材の根拠に置き換えてください。

```json
{
  "schema": 1,
  "id": "sample_short",
  "kind": "short",
  "title": "動画の内容に合った見出し",
  "source": "VOD/twitch_1234567890/source.mp4",
  "source_date": "2026-01-01",
  "cuts": [
    {
      "start": 100.0,
      "end": 125.0,
      "crop": {"x": 656, "y": 0, "w": 608, "h": 1080}
    }
  ],
  "captions": [
    {"start": 101.0, "end": 104.0, "text": "実際に聞き取れた発話", "speaker": "streamer"},
    {"start": 105.0, "end": 108.0, "text": "実際のコメント読み上げ", "speaker": "comment"}
  ],
  "blur_regions": [
    {"start": 110.0, "end": 114.0, "x": 700, "y": 40, "w": 300, "h": 200}
  ]
}
```

| 項目 | 意味 |
|---|---|
| `schema` | 整数 `1` |
| `id` | 英数字で始まる英数字・`_`・`-`。96文字以内。動画ごとに一意 |
| `kind` | `short`・`topic`・`digest` のいずれか。ノーカット全編の区分はありません |
| `title` | 内容に対応した題名。MP4 のメタデータにも保存 |
| `source` | 明示した元動画。workspace 外のファイルは拒否 |
| `source_date` | 実際の元配信日 `YYYY-MM-DD` |
| `cuts` | 完成動画の再生順。各 `start/end` は**元動画の絶対秒** |
| `crop` | 任意。元の映像ピクセルで `x,y,w,h`。整数・偶数、元フレーム内 |
| `captions` | 元動画の絶対秒と実発話。省略可能ですが、字幕が必要な成果物では必ず作成 |
| `blur_regions` | 元動画の絶対秒・元映像座標。必要箇所の時間限定ぼかし |
| `output` | 任意。workspace 内の `.mp4`。コマンドの `--output` が優先 |
| `outro` | 任意。`{"image":"assets/my-outro.png","duration":3}`。使用者自身が用意した画像 |

`cuts` の順番を勝手に並べ替えません。ダイジェスト冒頭に約10秒の見せ場を置き、その後に配信順の本編を続けられます。見せ場と本編で同じ区間を使用すると、その字幕・ぼかしも両方へ正しく対応します。約10秒は内容判断の目安で、発話を切る上限ではありません。

字幕が切点にまたがる場合や完成時間上で重複する場合はエラーにします。字幕だけを切り縮めて回避せず、元音声・語尾・笑い・反応を確認して切点または発話単位を修正してください。採用しない範囲の字幕は表示されません。

## 画面・字幕・音声

- ショートは `1080×1920 / 30fps`。元が縦 `9:16` でなければ、**各カットに目視で選んだ crop が必要**です。自動で顔や絵を探索する機能ではありません。
- crop の表示比率を保って枠全体を満たし、はみ出す部分だけ中央から切ります。人工の帯を足しません。crop を可能な限り `9:16` に近づけ、完成画面で主役・顔・頭の欠けを確認します。
- 横動画は `1920×1080 / 30fps`。元が `16:9` でない場合は、各カットに **表示比率が `16:9` となる crop** を目視で選びます。未指定・不適切な比率はエラーにします。SAR が 1 でない映像は `crop.w × SAR ÷ crop.h` を表示比率とし、表示比率を補正してから比例拡大します。縦横の引き伸ばしや人工の帯は使いません。
- 元映像のぼかしは crop より前に、指定した時刻・矩形だけへ適用します。ぼかし矩形の正しさ・読めなくなっていることは原寸で確認してください。
- 字幕は最大2行、白文字。本人は青縁、実際のコメント/TTS はピンク縁 `#F76AF8`。本人によるコメント復唱は `streamer` です。
- 設定済みの実フォントで幅を測ります。空白・句読点での改行に対応し、それでも読める大きさで入らない場合はエラーにします。日本語の自然な文節には EDL の `text` に `\n` を入れるか、発話を正しい時刻で別 cue にします。
- H.264＋AAC / 48kHz。`render.encoder: auto` は可搬性を優先して CPU の `libx264` を選びます。NVIDIA を使う場合は `h264_nvenc` を明示します。GPU 初期化の実テストで失敗すれば停止します。
- 音声は `source_preserve_v1`。元カットから PCM を作り、ゲイン変更・`loudnorm`・話者別補正・自動フェード・速度変更を適用しません。必要な 48kHz 変換と最終 AAC 圧縮だけを行います。
- 音声はフレーム尺による小さな隙間が積み重ならないよう PCM を別に接続します。映像は累計尺から30fpsのフレーム数を割り当て、音声とのずれを1フレーム程度に抑えます。
- outro は使用者の画像を比例縮小した任意の案内画面です。元配信の発話の後に付け、outro 部分だけ無音です。ユーザー素材の再配布はしません。

## 成果物と検査

MP4 と同じ場所に `.srt`（完成時間上の字幕）、`.ass`（焼き込みと同じ書式）、`.result.json` を保存します。JSON には元動画・EDL・完成品の SHA、尺、解像度、エンコーダー、検査結果、作業ディレクトリを記録します。

レンダー後に完成 MP4 の映像・音声を全体 decode します。完成音声を元 cuts の PCM と1秒ずつ比較し、全体のレベル差・区間別レベル差・残差・相関を記録します。全体0.6dB超・十分に聞こえる区間1.5dB超の予期しないレベル変化、元の音声にない無音化、大きな尺の差は停止条件です。AAC は非可逆圧縮なので残差ゼロは期待しません。元からのノイズ、音節の切断をこの数値だけで合格にしません。

`human_qa.status` は常に `pending` から始まります。採用区間の聴取、発話の前提と文末、字幕の正確さ・話者・見切れ、縦横比、ぼかしの全該当範囲を完成品で確認して、制作ジョブ側の QA 正本に記録します。自動検査結果を人の視聴証拠として転記しないでください。非公開アップロードは別工程です。

元動画と最終媒体の SHA は、投稿ワークフローと共用の `editing/cache/media-sha256-v1` を使います。同一最終 SHA と同一入力の合格済み decode は再利用します。`.work/renders/<id>/<fingerprint>/` には EDL の写し、PCM、字幕、カット処理、ログを保持します。長時間のレンダーは親スキルから `run_stage.py` で実行し、同時に別の大規模レンダー・ASRを動かさないでください。

## 実素材を使わない動作確認

```powershell
./.venv/Scripts/python.exe -m unittest discover -s tests -p test_render.py -v
```

短いテスト映像と正弦波を生成し、3種類の実エンコード、PCM/AAC比較、ショートの画素比較、字幕時刻、非時系列の導入、上書き拒否・改訂保存、検査再利用、端数カット、任意の末尾画像を確認します。Twitch・YouTube・Canva へ送信しません。必要な FFmpeg・フォント・Python依存がない場合、統合テストは `skipped` と報告します。`skipped` を実エンコード成功と読み替えないでください。
